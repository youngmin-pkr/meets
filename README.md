# 동행 플랫폼 (meets)

행사 동행 매칭 앱입니다. 규칙은 `docs/정리문서.md`, 작업 방식은 `CLAUDE.md`를 보세요.

## 웹에서 보기

**https://youngmin-pkr.github.io/meets/** (main 브랜치에 코드가 들어오면 자동으로 새로 올라갑니다)

- 서버 없이 브라우저 안의 가짜 서버(`apps/mobile/src/demoBackend.ts`)로 동작합니다. 새로고침하면 처음으로 돌아갑니다.
- 나이 판정, 별명 규칙, 약관 같은 규칙은 실제 서버와 같은 `packages/shared` 코드를 씁니다.
- 해 볼 것:
  - 생년월일은 6자리(`000501`)나 8자리(`20000501`)로 넣습니다. `150101`이면 가입 불가, `100101`이면 청소년 안내, `000101`이면 가입됩니다.
  - 별명 `동행러`는 이미 쓰이는 별명으로 넣어 두었습니다. `카톡민지`처럼 연락처·SNS가 보이는 별명은 막힙니다.
  - 같은 테스트 사용자 번호로 '이미 계정이 있어요'를 누르면 멈췄던 단계부터 이어집니다.
  - 가입을 마치면 예시 행사(모두 지어낸 이름) 목록이 나옵니다. '찾는 행사가 없나요?'로 제보할 수 있고, 같은 공식 링크는 하나로 합쳐집니다.
  - 행사를 고르고 일정·템포·몰입도·필수 조건을 입력하면, 지어낸 예시 사용자 7명 중 조건이 맞는 사람이 후보로 나옵니다.
  - 조건을 아주 좁게 고르면 '후보 없음' 화면에서 조건 넓히기(예상 후보 수)와 알림 신청을 해 볼 수 있습니다.
  - 후보 화면의 '티켓 인증하기'에서 아무 캡처 이미지를 올리고, 끌어서 가린 뒤, 아무 예매번호(4자 이상)를 넣으면 인증이 끝납니다. 데모에서는 이미지를 저장하지 않습니다.
  - 인증 뒤 후보 상세에서 날짜·구간·만날 장소를 골라 제안을 보낼 수 있습니다. **데모 전용:** 예시 사용자는 3초 뒤 자동으로 수락하고, 후보를 처음 볼 때 예시 사용자 한 명이 나에게 제안을 보냅니다. 홈의 '받은 제안'에서 수락하면 약속(확정 대기)이 생깁니다.
- 실제 서버(권한 검사, DB 제약, 개인정보 보호)는 `apps/server`에 있고, 테스트로 확인합니다.

## 정해진 것

- 기술 스택: React Native·Expo / NestJS / PostgreSQL(Prisma) / FCM 푸시 / 직접 만드는 채팅
- 본인 확인: 업체가 정해지기 전까지 **테스트용 가짜 본인 확인**(`fake`)을 씁니다. 실제 서비스(`NODE_ENV=production`)에서는 서버가 시작하지 않습니다.
- 같은 별명은 쓸 수 없습니다 (영문 대소문자 구분 없음). 별명은 2~10자 (정책 값).
- '같은 팬을 먼저 보여 주세요'는 팬덤을 고르면 항상 켜진 것으로 봅니다.
- 생년월일·이름·전화번호는 저장하지 않습니다. 같은 사람 확인용으로 CI의 해시만 저장합니다.
- 청소년(만 14~17세)은 법률 검토가 끝날 때까지 가입하지 못하고 안내만 봅니다.
- 일정이 바뀐(변경됨) 행사도 다시 바꾸거나 취소할 수 있습니다. (정리문서 행사 상태 표에 추가)
- 운영 콘솔(운영자 화면)은 나중에 요청할 때 데모 모드로 만듭니다.
- 작업은 PR로 올리고, 테스트가 모두 통과하면 Claude가 직접 합칩니다.
- 생년월일·성별은 매칭의 필수 조건(나이 범위·같은 성별)에만 쓰고 다른 사용자에게 보여 주지 않습니다.
- 순서: 3-1(입력 흐름·후보) → 6단계(티켓 인증) → 3-2(제안). 제안은 티켓 인증을 마친 사람만 보낼 수 있습니다.
- 티켓 캡처는 OCR 업체 없이 사용자가 예매번호·입장 가능한 날을 직접 적고, 무작위 20%·중복 의심·신고 재검증은 사람이 검수합니다.
- 후보 순서: 몰입도 → 같은 팬 → 티켓 인증 → 참석 예정 → 인증 전.
- 제안은 후보 목록과 같은 규칙으로 보낼 수 있고, 상대의 약속 조건과 맞는지는 받는 사람이 보고 수락·거절로 정합니다.

## 1단계에서 만든 것: 가입·본인 확인

시작 → 약관 동의 + 본인 확인 → (성인) 별명·색 → 팬덤(건너뛰기 가능) → 준비 완료(알림 권한 한 번만)

- 만 14세 미만, 청소년은 계정을 만들지 않고 안내 화면만 보여 줍니다.
- '이미 계정이 있어요'는 본인 확인을 다시 해서 같은 사람이면 기존 계정으로 들어갑니다.

| 주소 | 하는 일 |
| --- | --- |
| `GET /signup/config` | 약관, 별명 글자 수, 팬덤 최대 개수 등 |
| `POST /auth/identity` | 본인 확인 결과로 가입 또는 로그인 |
| `GET /me` | 내 정보와 다음 가입 화면 |

| `POST /me/notification-choice` | 알림 권한 선택 (한 번만) |

## 2단계에서 만든 것: 행사 데이터와 운영 기능(서버)

- 사용자 앱: 행사 선택(분류·검색), 고른 행사 보기, 행사 제보(공식 링크 필수, 같은 링크는 합침)
- 서버: 행사 상태 전이 표, 운영자 권한표(역할 4 × 기능 10), 두 명 확인(행사 취소), 운영자 기록(AuditLog)
- **운영 콘솔 화면은 아직 없습니다.** 나중에 요청하면 만듭니다. 그 전까지 운영 기능은 서버 주소로만 쓸 수 있습니다.

| 주소 | 하는 일 | 권한 |
| --- | --- | --- |
| `GET /events?q=&category=` | 행사 목록 (등록·변경된, 끝나지 않은 행사) | 사용자 |
| `GET /events/:id` | 행사 상세 (공개된 만날 장소만) | 사용자 |
| `POST /event-reports` | 행사 제보 | 사용자 |
| `POST /admin/auth/login` | 운영자 로그인 | - |
| `GET/POST /admin/events`, `GET/PUT /admin/events/:id` | 행사 목록·등록·상세·수정 | 행사 담당, 관리자 |
| `POST /admin/events/:id/review` · `approve` · `reject` | 제보 검수 | 행사 담당, 관리자 |
| `POST /admin/events/:id/cancel-proposals` | 행사 취소 제안 | 행사 담당 |
| `POST /admin/event-cancellations/:id/confirm` | 행사 취소 확정 | 관리자 |

## 3-1단계에서 만든 것: 입력 흐름과 후보 매칭

- 입력 흐름: 일정(가고 싶은 날, 도착·귀가 시간, 구간별 같이/혼자) → 템포(질문 3개) → 몰입도(행사 종류에 맞는 질문 2개) → 필수 조건(성별, 나이, 꼭 지킬 약속)
- 매칭 4단계(`packages/shared/src/matching.ts`, 서버와 데모가 같은 코드 사용)
  1. 필수 조건으로 거르기 (나이·성별은 양쪽 조건을 모두 확인, 약속은 내가 고른 것을 상대도 골랐어야 함)
  2. 템포 차이 1단계 이내 + 같이할 시간이 2시간 이상 겹침 (내가 고른 시간이 더 짧으면 그만큼)
  3. 몰입도가 가까운 순 (1단계 이내, 후보가 3명보다 적으면 2단계까지 넓히고 '짧은 구간부터' 안내)
  4. 같은 순위 안에서는 같은 팬 먼저
- 후보 없음: 함께할 시간 줄이기(1시간 이상 겹침), 몰입도 한 단계 더, 다른 날짜 — 바꾸기 전에 예상 후보 수를 보여 줌. 안전 조건은 넓히지 않음
- 알림 신청: 행사 3일 전까지 (실제 알림 보내기는 4단계에서 연결)
- 숫자 기준은 모두 정책 값(`MATCH_*`, `WAIT_ALERT_END_DAYS_BEFORE`)

| 주소 | 하는 일 |
| --- | --- |
| `GET/PUT /events/:id/preference` | 입력 흐름 불러오기·저장 |
| `GET /events/:id/candidates?dayId=&sort=&shortTime=&immersionPlus=` | 후보 목록 (0명이면 예상 후보 수 포함) |
| `GET /events/:id/candidates/:userId` | 후보 상세 (왜 잘 맞는지, 공개한 팬덤) |
| `POST /events/:id/wait-registrations` | 후보 없음 알림 신청 |

## 6단계에서 만든 것: 티켓 인증

- 흐름: 안내 → 캡처 올리기 → 끌어서 가리기 → 예매번호·입장 가능한 날 적기 → 인증 완료 / 확인 중 / 실패
- 서버는 가릴 곳을 검게 칠하고 사진 속 숨은 정보(위치·기기 정보)를 지운 이미지만 잠깐 저장하고, 확인이 끝나면 바로 지웁니다. 원본은 저장하지 않습니다.
- 예매번호는 원문 없이 해시로만 저장하고, 같은 행사에서 다른 계정이 같은 번호를 쓰면 '중복 의심'으로 사람이 확인합니다.
- 무료·예약제 행사는 예약 확인 화면으로 인증하거나 '참석 예정'으로 시작할 수 있습니다.
- 인증한 사람은 티켓으로 입장할 수 있는 날만 후보에 나옵니다.
- 인식기 연결부(`apps/server/src/tickets/ticket-recognizer.ts`)만 바꾸면 나중에 OCR 업체를 붙일 수 있습니다.

| 주소 | 하는 일 | 권한 |
| --- | --- | --- |
| `GET /events/:id/ticket` | 내 인증 상태 | 사용자 |
| `POST /events/:id/tickets` → `POST /tickets/:id/image` → `POST /tickets/:id/confirm` | 시작 → 가린 캡처 올리기 → 내용 확인 | 사용자 |
| `POST /events/:id/attendance-plan` | 참석 예정 (티켓이 필요 없는 행사만) | 사용자 |
| `GET /admin/ticket-reviews` | 검수 목록 (중복 의심 → 신고 재검증 → 인식 실패 → 무작위) | 검수자, 관리자 |
| `GET /admin/ticket-reviews/:id/image` | 가린 이미지 보기 (검수 중에만, 기록 남음) | 검수자만 |
| `POST /admin/ticket-reviews/:id/approve` · `reject` · `hold` | 승인 · 반려 · 보류 | 검수자, 관리자 |
| `POST /admin/tickets/:id/reverify` | 신고로 재검증 요청 | 신고 담당, 관리자 |

## 3-2단계에서 만든 것: 제안과 약속

- 제안 보내기: 후보 상세에서 날짜 → 구간(처음엔 짧게) → 만날 장소(공개된 장소만)
- 보낼 수 있는 사람: 티켓 인증, 또는 티켓이 필요 없는 행사의 '참석 예정'(구간 1개까지)
- 받는 사람도 인증(또는 참석 예정)을 마쳐야 수락할 수 있고, 거절은 언제든 가능
- 만료: 24시간, 행사 24시간 전이 더 빠르면 그때까지 (정책 값). 같은 두 사람 사이에는 답을 기다리는 제안이 하나만
- 수락하면 약속이 '확정 대기'로 만들어집니다.
- 제안 상태 전이 표(보냄 → 수락/거절/만료/취소)는 `ProposalStateService` 한 곳에서만 바꿈
- 홈: 다가오는 약속, 받은 제안·보낸 제안

| 주소 | 하는 일 |
| --- | --- |
| `POST /events/:id/proposals` | 제안 보내기 |
| `GET /me/proposals` | 받은·보낸 제안 (만료된 것은 자동으로 만료 처리) |
| `POST /proposals/:id/accept` · `reject` · `cancel` | 수락(약속 생성) · 거절 · 취소 |
| `GET /me/appointments` | 내 약속 |

## 4단계에서 만든 것: 약속 확정·전날 확인·취소·알림

- 전날 확인: 약속 전날 18시에 확인 요청 → 둘 다 '갈 수 있어요'를 누르면 확정. 확인하지 않은 사람에게 마감 3시간 전에 재촉 1번, 약속 3시간 전 마감까지 확인이 없으면 취소되고 '무응답'으로 기록
- 취소: 확정 전·후 모두 가능, 사유(선택)는 상대에게 전달. 약속 24시간 안의 취소는 '임박 취소'로 기록 (신뢰 단계 반영은 7단계)
- 당일: 1시간 전 알림, '도착했어요'(1시간 전부터), 약속 시각에 '만남 중', 끝나면 '종료'. 내가 도착했고 상대 기록이 없으면 15분 뒤부터 '안 나왔어요' → 중간 종료 (판단은 7단계 신고 처리에서)
- 행사 일정이 바뀌면: 시간이 달라진 약속만 '다시 정하기' → 둘 다 다시 확인하면 확정, 48시간(행사가 가까우면 행사 12시간 전) 안에 못 정하면 '보류'. 행사가 취소되면 약속은 '자동 종료'
- 시간이 겹치는 약속은 만들 수 없음 (제안 보낼 때·수락할 때·다시 확인할 때 검사)
- 앱 안 알림함: 제안 도착·수락·거절, 전날 확인·재촉, 확정, 취소, 1시간 전, 상대 도착, 일정 변경·보류, 행사 취소. 푸시는 업체를 정한 뒤에 붙이고, 방해 금지 시간(22시~8시)에는 푸시를 아침 8시로 미루도록 시각을 함께 저장
- 시간이 되어 저절로 일어나는 일은 서버가 1분마다 처리하고, 약속을 볼 때도 먼저 처리
- 약속을 만들 때의 정책 값을 함께 저장해서, 정책 값이 바뀌어도 이미 만든 약속에는 소급하지 않음
- 약속 상태 전이 표는 `AppointmentStateService` 한 곳에서만 바꿈
- 홈: 오늘 할 일, D-day, 알림(빨간 점), 참석 인증 표시, 행사 종류 바로가기
- 데모 전용: 가입하면 '내일 약속'이 하나 들어 있어 전날 확인을 바로 해 볼 수 있고, 예시 상대는 확인 요청이 열리면 몇 초 뒤 확인합니다

| 주소 | 하는 일 |
| --- | --- |
| `GET /appointments/:id` | 약속 하나 (누를 수 있는 버튼 포함) |

## 5단계에서 만든 것: 앱 안 채팅과 연락처 차단

- 제안을 수락해 약속이 생기면 두 사람의 채팅이 열리고, 만남이 끝나고 24시간 뒤 닫힘. 취소·행사 취소면 바로 닫힘 (닫힌 뒤에는 읽기만)
- 글자만 보낼 수 있음 (사진·위치 없음), 한 번에 500자까지
- 연락처·SNS(번호, 이메일, SNS 아이디, 링크, 메신저 이름)는 보내기 전에 멈추고 경고. '그래도 보낼게요'를 고르면 보내지고 감지 종류가 기록됨. 앱을 거치지 않고 보내도 서버에서 다시 검사
- 메시지 내용은 로그·오류 응답에 남기지 않음. 운영자가 대화를 보는 길은 아직 없음 (신고 건 열람은 7단계)
- 약속 상태가 바뀌면 대화창에 안내 줄 (확정, 취소, 도착 등)
- 빠른 버튼: '도착했어요'(도착 기록과 같음), '조금 늦어요'
- 새 메시지는 채팅 화면이 열려 있는 동안 3초마다 확인 (나중에 실시간 연결로 바꿀 수 있게 한 곳에 모아 둠)
- 새 메시지는 알림함에 쌓지 않고, 홈·약속·아래쪽 메뉴에 '안 읽은 메시지' 수만 표시
- 아래쪽 메뉴: 홈 · 행사 · 채팅 ('나'는 그 화면을 만들 때 추가)
- 대화 기록 보관 기간은 임시로 180일 (`TODO(법률 검토)`), 실제 삭제는 7단계에서
- 데모 전용: 예시 상대가 인사를 보내고, 내가 메시지를 보내면 몇 초 뒤 정해진 답장을 보냄

## 7-1단계에서 만든 것: 후기 · 신뢰 단계 · 차단 · 신고 접수

- **후기**: 만남이 정상적으로 끝나면 양쪽에 후기 요청(알림). 끝나고 7일 안에 한 번, 어땠어요 → 칩(건너뛰기 가능) → 또 같이 가고 싶어요?
  후기 내용은 상대에게 어떤 길로도 보이지 않음(읽는 주소가 없음). 취소·중간 종료·행사 취소된 약속에는 후기 요청이 없음
- **서로 '또 같이 가고 싶어요'**면 둘 다에게 알리고, 채팅이 닫히지 않고, 다음 행사 후보 목록 맨 위에 보임. 한쪽만이면 상대에게 아무것도 알리지 않음
- **신뢰 단계**: 1 기본 · 2 참석 예정 · 3 참석 인증 · 4 쌓인 신뢰. 숫자 점수는 저장·표시하지 않고, 바뀔 때마다 이유와 함께 기록(`TrustChange`). 지금은 보여 주기만 함(후보 카드 '쌓인 신뢰' 표시)
  - 4단계: 3단계에서 받은 '좋았어요·괜찮았어요' 후기 3건 이상 + 운영팀이 확인한 불편 신고 0건
  - 하락: 최근 90일 임박 취소·무응답·확인된 노쇼가 2번 이상이면 한 단계
- **차단**: 서로 후보에서 숨김(후보 상세·제안도 막힘), 상대에게 알림 없음. 답을 기다리는 제안은 조용히 취소, 진행 중인 약속은 끝나고(차단한 사람에게 임박 취소 기록 없음, 상대에게는 이유 없이 취소로만 보임), 채팅은 닫힘. 풀어도 이전 약속은 살아나지 않음
- **신고 접수**: 분류 7가지 + 자세한 내용(선택) + 같이 차단. 신고한 사람 정보는 상대에게 공개되지 않고 알림도 없음. 우선순위는 도움 요청 > 청소년 > 일반. 신고 상태는 `ReportStateService` 한 곳에서만 바꿈. 운영팀이 처리하는 기능은 7-2단계
- 아래쪽 메뉴에 **나** 탭: 내 신뢰 단계, 받은·보낸 제안, 알림, 차단한 사람
- 데모 전용: 가입하면 어제 끝난 만남(지우)이 있어 후기를 바로 남겨 볼 수 있고, 지우는 이미 '또 같이 가고 싶어요'를 골라 둔 상태

| 주소 | 하는 일 |
| --- | --- |
| `POST /appointments/:id/review` | 후기 남기기 (`overall`, `goodTags`, `badTags`, `again`, `hideTarget`) |
| `GET /me/trust` | 내 신뢰 단계 (단계 이름만) |
| `GET /me/blocks` · `POST /blocks` · `POST /blocks/from-chat` · `DELETE /blocks/:userId` | 차단 목록 · 차단 · 약속 상대 차단 · 해제 |
| `POST /reports` | 신고 접수 (`appointmentId`, `category`, `detail`, `alsoBlock`) |

## 7-2단계에서 만든 것: 신고 처리 (운영, 서버 기능)

운영 콘솔 **화면**은 아직 없고, 서버 기능과 규칙만 있습니다. 모든 주소는 서버에서 로그인과 권한표를 검사합니다.

- **대기열**: 접수된 신고는 우선순위(도움 요청 > 청소년 > 일반)와 함께 바로 대기열에 올라가고, 같은 순위에서는 오래된 것이 먼저. 목록에는 이름·내용이 없고 상세에서만 보임
- **담당 지정**: 대기 → 처리 중. 한 사람만, 이후에는 담당자만 조치할 수 있음
- **대화 기록 열람**: 이 신고 건에서만, 담당자인 **신고 담당만**(관리자도 불가), 사유를 5자 이상 적어야 열리고 열 때마다 사유와 함께 AuditLog에 남음. 기록에는 대화 내용이 들어가지 않음
- **조치**: 조치 없음 / 기록만 남기기 / 경고 / 기능 제한 7일(제안 보내기·수락만 막고 채팅은 가능). 조치 없음이 아니면 '사실로 확인'으로 기록되어 신뢰 단계에 바로 반영. 신고한 사람에게는 결과 알림(조치 내용 없이), 경고·제한은 정해진 문장의 운영 안내
- **이용 정지**: 신고 담당이 제안하고 **다른 관리자**가 확정(두 명 확인). 확정되면 로그인이 풀리고, 답을 기다리던 제안은 취소되고, 진행 중인 약속은 끝나며(상대에게는 이유 없이 취소로만 보임), 후보에서도 사라짐. 관리자가 되돌릴 수도 있음(처리 중으로 복귀)
- **'안 나왔어요'**를 누르면 노쇼 분류로 대기열에 올라가고, 운영팀이 양쪽 도착 기록을 보고 사실로 확인하면 상대의 노쇼로 기록되어 신뢰 단계 하락(최근 90일 2번)에 셈
- 모든 열람(목록·상세·대화)과 변경(담당 지정·조치·정지 제안·확정·되돌림)은 누가·언제·왜 했는지 AuditLog에 기록
- 신고 상태 전이 표 전체와 운영자 권한(역할별)을 서버 테스트로 확인

| 주소 | 하는 일 | 할 수 있는 역할 |
| --- | --- | --- |
| `GET /admin/reports` · `GET /admin/reports/:id` | 대기열 · 상세 | 신고 담당, 관리자 |
| `POST /admin/reports/:id/claim` | 담당자로 지정 | 신고 담당, 관리자 |
| `POST /admin/reports/:id/chat` | 대화 기록 열람 (`reason` 필요) | **신고 담당만** |
| `POST /admin/reports/:id/resolve` | 조치하고 종결 (`action`, `reason`) | 신고 담당, 관리자 (담당자만) |
| `POST /admin/reports/:id/suspension-proposals` | 이용 정지 제안 | **신고 담당만** |
| `POST /admin/user-suspensions/:id/confirm` · `decline` | 정지 확정 · 되돌림 | **관리자만** (제안한 사람은 불가) |

## 8단계에서 만든 것: 만남 중 안전

- **벗어나고 싶어요(도움 요청)**: 도착 버튼이 열린 뒤(약속 1시간 전)부터 약속이 끝날 때까지, 확정·만남 중인 약속에서 한 번 눌러 끝냅니다. 채팅이 바로 닫히고, 상대에게는 이유 없이 '약속이 취소됐어요'만 보이며, 운영팀 대기열에 도움 요청으로 가장 먼저 올라갑니다. 차단은 따로 정하지 않습니다. 그 밖의 때에는 신고로 안내합니다. (정리문서 5장 상태 전이표에 '확정 → 중간 종료' 한 줄을 추가했습니다)
- **안전 확인**: 만남이 시작되고 60분 뒤부터 60분 간격으로 최대 2번 '잘 만나고 계세요?'. 답이 없으면 10분 뒤 한 번 더, 그래도 없으면 10분 뒤 믿는 사람 링크에 알림이 뜹니다(미리 켜 둔 경우만). 방해 금지 시간에도 바로 알리고, 상대에게는 보이지 않습니다. 1시간보다 짧은 만남은 묻지 않습니다. 기본은 켜짐.
- **믿는 사람에게 알리기**: 링크 하나로 행사·시간·장소·함께하는 사람의 별명만 보입니다. 연락처·계정·채팅은 없고, 약속이 끝나고 6시간 뒤(정책 값 9) 사라지며, 만든 사람이 끌 수 있습니다. 주소는 서명이 붙어 있어 고치면 열리지 않고, 없는·꺼진·지난 링크는 모두 같은 답입니다. 연락처(전화번호)는 받지 않아 문자 발송 업체가 필요 없습니다. '믿는 사람에게도 알리기' 설정은 기본 꺼짐.
- **설정**: 마이 > 안전 설정

## 9-1단계에서 만든 것: 일행 만들기와 일행 후보

- **일행**: 성인 2~4명. 후보 화면의 '친구와 같이 가나요?'에서 만들고, 초대 링크(서명된 주소, 48시간, 연락처 없음)를 친구에게 보냅니다. 친구는 나 탭 > 일행 > 초대 링크로 합류합니다.
- **전원 입력**: 일정·스타일 입력과 티켓 인증(또는 참석 예정)을 모두 마쳐야 '입력 마침'. 전원이 마치면 일행이 '활성'이 되어 후보가 열립니다. 대표는 입력하지 않은 친구를 빼고 진행할 수 있습니다(입력을 마친 사람이 2명 이상일 때). 합류 24시간 뒤에도 입력하지 않으면 재촉 알림 1번.
- **일행 후보**: 같이 볼 시간은 전원이 겹치는 시간, 템포·몰입도는 가장 낮은(느긋한) 사람 기준. 꼭 지킬 조건(나이·성별·약속)은 일행 한 명 한 명 모두에게 맞아야 하고, 일행 중 누구와든 차단 관계인 사람은 숨깁니다.
- **빠지기·해체**: 누가 빠져도 남은 사람끼리 계속하고, 한 명만 남으면 일행이 풀립니다. 대표가 빠지면 가장 먼저 합류한 사람이 대표가 됩니다. 행사가 끝나면 일행도 풀립니다.
- 일행 상태는 `PartyStateService` 한 곳에서만 바꾸고, 전이 표(정리문서 5장)는 서버·shared 테스트로 전체 확인합니다. 정리문서에 표 3줄(제안 중 → 활성, 초대 중·확인 중·제안 중 → 해체)을 추가했습니다.

| `POST/GET /events/:eventId/party` | 일행 만들기 · 이 행사의 내 일행 |
| `GET /me/parties` · `GET /parties/:id` | 내 일행들 · 일행 하나 |
| `POST /parties/:id/leave` · `disband` · `proceed` | 빠지기 · 해체(대표) · 입력 안 한 친구 빼고 진행(대표) |

## 9-2a단계에서 만든 것: 여러 명이 만나는 약속 (기반 작업, 사용자 화면은 아직 그대로)

일행으로 제안하는 길(9-2b)은 아직 없어서, 지금은 테스트에서만 여러 명 약속(일행 2~4명 + 상대)을 만듭니다. 그래도 기존 기능이 모두 여러 명에서 맞게 동작하도록 서버를 넓혔습니다. 1:1 약속은 그대로입니다.

- **쪽(side)**: 약속 참여자는 제안을 보낸 쪽(A)과 받은 쪽(B)으로 나뉩니다. 약속에서 빠진 사람은 `leftAt`·`leftReason`으로 남기고, 그 사람에게는 끝난 약속으로 보입니다. 약속 응답에 `companions`(함께하는 사람들, 상대 쪽이 먼저)가 추가됐습니다.
- **전날 확인**: 전원이 확인하면 확정. 마감까지 확인하지 않은 사람만 빠지고, 양쪽에 확인한 사람이 남으면 확정됩니다. 한 쪽에 아무도 없으면 취소.
- **취소·빠지기**: 일행 중 한 명이 취소하면 그 사람만 빠집니다. 쪽이 비면 약속이 취소됩니다. 확정된 약속이면 상대 쪽이 다시 확인합니다(다시 정하기, 사유 '인원 변경', 약속 시작 전까지·최대 48시간, 못 하면 보류). 임박 취소는 빠진 사람에게만 기록됩니다.
- **노쇼**: 도착하지 않은 사람마다 신고가 접수되고, 다른 사람이 아무도 도착하지 않았을 때만 만남이 끝납니다. 같은 사람이 두 번 누를 수는 없습니다.
- **채팅**: 단체 채팅(보낸 사람 별명 표시, 연락처 감지는 그대로). 약속에서 빠진 사람은 읽을 수 없습니다. 서로 '또 같이 가고 싶어요'를 골라도 여러 명 약속의 채팅은 24시간 뒤 닫힙니다.
- **후기**: 함께한 사람마다 따로 남깁니다(`targetId`). 같은 일행끼리·빠진 사람과는 남기지 않습니다. 서로 '또 같이 가고 싶어요'인 한 쌍은 다음 행사 후보에서 서로 먼저 보입니다(후기로 계산하도록 바꿈).
- **신고·차단**: 누구인지(`targetId`)를 알려야 합니다. 차단하면 차단한 사람이 약속에서 빠집니다(쪽이 비면 약속 종료).
- **도움 요청**: 일행이 있으면 누른 사람만 빠지고 나머지는 계속합니다. 상대 쪽 모든 사람이 신고 대상(도움 요청 우선순위)입니다. 쪽이 비면 약속이 끝나고 채팅이 닫힙니다. 1:1은 그대로.
- **안전·링크**: 빠진 사람에게는 안전 확인을 묻지 않고, 믿는 사람 링크에는 함께하는 사람들 별명이 모두 보입니다.
- 알림 문구는 '하늘님 외 2명'처럼 묶어서 보여 줍니다.

알려진 한계: 다시 정하기 중에는 취소(빠지기)가 막혀 있어, 그 사이에 일행이 또 빠져야 하면 기한이 지나 보류된 뒤에야 정리됩니다. 사용자 화면(약속 화면의 여러 명 표시, 후기 대상 고르기 등)은 9-2b에서 만듭니다.

## 9-2b단계에서 만든 것: 일행으로 제안하기

- **일행 → 개인 제안**: 일행의 후보 목록에서 한 사람을 고르고 날짜·구간·장소를 정하면 **초안**이 만들어지고, 나머지 일행원 전원에게 동의 요청이 갑니다. 전원이 동의하면 제안이 나가고(그때부터 24시간) 일행은 '제안 중'이 됩니다. 한 명이라도 동의하지 않거나 24시간 안에 모이지 않으면 초안이 취소·만료됩니다. 한 일행은 진행 중인 제안을 하나만 가질 수 있고, 일행 중 누구라도 그 시간에 다른 약속이 있거나 제안 제한 중이면 만들 수 없습니다. (일행끼리 제안하거나 개인이 일행에게 제안하는 것은 아직 없습니다)
- **받는 사람**: 초안은 보이지 않고, 제안이 나가면 '하늘님 외 2명이 제안했어요'로 보입니다. 수락하면 일행 전원(보낸 쪽 A)과 받은 사람(B)이 함께하는 약속이 만들어집니다. 일행 전원이 겹치지 않는 시간이 생겼거나 누구든 그 시간에 다른 약속이 생겼으면 수락할 수 없습니다.
- **끝난 뒤**: 거절·만료·취소·수락 모두 일행은 '활성'으로 돌아갑니다. 보낸 제안은 일행원 누구나 취소할 수 있습니다.
- **일행이 바뀔 때**: 초안 중에 빠지면 그 사람의 동의가 필요 없어지고(남은 사람이 모두 동의한 상태면 바로 나감), 만든 사람이 빠져도 초안은 계속됩니다. 보낸 뒤에 빠져도 제안은 계속되고 수락하면 남은 사람들과 약속이 됩니다. 한 명만 남아 일행이 풀리면 초안은 취소되고 보낸 제안은 남은 사람의 개인 제안으로 바뀝니다. 대표가 풀면 초안·제안 모두 취소됩니다.
- **제안 상태**: 정리문서 제안 표에 '초안' 3줄을 추가했습니다. 제안·일행 상태는 각각 `ProposalStateService`·`PartyStateService`에서만 바꾸고, 제안이 끝나면 일행 상태도 그곳에서 함께 바꿉니다.
- **앱 화면**: 일행 화면에 제안 카드(동의 현황, 동의/동의하지 않아요, 취소), 일행 후보에서 후보를 고르고 제안 만들기, 내 제안 목록에 일행 이름과 동의 요청, 홈 '오늘 할 일'에 동의 요청. 약속·채팅·후기·신고·차단 화면은 여러 명을 보여 줍니다(약속 화면의 사람별 확인·도착, 단체 채팅의 보낸 사람 별명, 후기는 한 사람씩 이어서, 신고·차단은 대상을 고름).
- 데모에서는 예시 친구가 잠시 뒤 동의하고, 받는 예시 사용자는 수락하면 약속이 만들어집니다. (데모의 여러 명 약속은 화면 표시만 여러 명이고, 확인·도착 같은 동작은 나와 상대 기준입니다)

| 주소 | 하는 일 |
| --- | --- |
| `POST /parties/:id/proposals` | 일행 제안 초안 만들기 (일행원) |
| `POST /proposals/:id/agree` · `decline` | 초안에 동의 · 동의하지 않음 (나머지 일행원) |
| `GET /me/proposals` | 내 제안 (일행 정보와 동의 현황 포함) |
| `POST /proposals/:id/cancel` | 취소 (보낸 사람, 일행이 보냈으면 일행원 누구나. 초안도 가능) |

알려진 한계: 일행 → 일행, 개인 → 일행 제안은 일행이 후보로 보이는 목록이 필요해서 아직 없습니다. 일행 제안은 '참석 예정'일 때의 짧은 구간 제한을 적용하지 않습니다.

## 10-1단계에서 만든 것: 즉석 동행 '지금 갈래요' (켜기·대기·후보)

- **켜기**: 행사 당일, 행사 시간 안에 '지금 행사장에 있어요'를 직접 켜면 60분 동안(행사 끝·22시를 넘지 않음) 후보 풀에 들어갑니다. 다시 켜면 60분 더, 끄면 바로 빠집니다. **위치(좌표)는 받지도 저장하지도 않습니다.** (GPS로 행사장 안인지 확인하는 방식은 위치 정보 이용 동의를 정한 뒤 `TODO(법률 검토)`)
- **대기**: 나를 뺀 대기 인원이 5명 미만이면 사람 수만 보이고 개인은 보이지 않습니다. 5명이 되면 후보 목록이 열리고, 대기 중에 켠 사람에게 알림이 한 번(하루 한 번) 갑니다. 서로 차단한 사람은 세지도 보이지도 않습니다.
- **후보**: 기존 매칭 규칙(나이·성별·약속 양쪽 확인, 템포·몰입도)을 그대로 쓰고, 지금부터 60분 시간대에서 30분 이상 겹쳐야 합니다. 저장된 입력(스타일·필수 조건)이 있으면 그대로, 없으면 켤 때 간단히 5문항에 답합니다(한 번 답하면 기억).
- **쓸 수 없는 경우**: 청소년·이용 정지, 최근 90일 안에 확인된 노쇼, 이용 제한 중, 행사 날이 아니거나 행사 시간 밖, 22시 이후.
- **앱**: 홈에 '지금 갈래요' 카드(오늘 쓸 수 있는 행사가 있을 때), 대기 인원 표시, 후보 목록. 데모에는 '오늘 열리는 테스트 팝업 마켓'이 있고 예시 사용자 4명이 행사장에 있다가 켠 뒤 잠시 뒤 6명이 되어 후보가 열립니다. (22시 이후에는 닫힘)

| 주소 | 하는 일 |

| `GET /me/instant-events` | 오늘 쓸 수 있는 행사 (홈의 지금 갈래요) |
